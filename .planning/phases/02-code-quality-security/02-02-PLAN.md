## Objective

Sanitize error messages to prevent information disclosure by removing internal IDs and stack traces from client-facing responses while preserving debugging information in logs.

---

## Context

### Research Findings from RESEARCH.md
- OWASP guidelines recommend generic error messages for clients
- Internal details should be logged, not returned to clients
- Current code exposes IDs in error messages (e.g., `Offer with ID ${id} not found`)

### Existing Code Patterns
- Services throw exceptions with detailed messages including IDs
- No separation between client-facing and debug information

---

## Tasks

### Task 1: Sanitize Merchant Service Errors

**Type:** feature
**Files:** `src/modules/merchant/merchant.service.ts`

**Action:**
Replace error messages that expose internal IDs with generic messages:
```typescript
// Before:
throw new NotFoundException(`Merchant with ID ${id} not found`);
throw new NotFoundException(`Branch not found`);

// After:
this.logger.warn(`Merchant not found: ${id}`);
throw new NotFoundException('Merchant not found');

this.logger.warn(`Branch not found: ${branchId}`);
throw new NotFoundException('Branch not found');
```

**Verify:**
- No error messages contain IDs from parameters
- Internal details logged before throwing
- Generic messages used for NotFoundException, ForbiddenException

**Done:** Merchant service errors sanitized
